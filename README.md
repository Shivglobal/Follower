Problem Statement: Directed Social Graph Modeling1. Core ConceptYou are modeling a Directed Graph (or Digraph) where:Nodes (Vertices): Represent the users in the network (e.g., User1, User2, etc.).Directed Edges: Represent a unidirectional relationship between two users, specifically a Follow action (Follower -> Followee or Follower -> Celebrity).Because it is directed, a connection from User1 to User2 means User1 follows User2, but it does not automatically mean User2 follows User1 back.2. Input Data BreakdownBased on the relationships you provided:User1 -> User2 (User1 follows User2)User2 -> User3 (User2 follows User3)User3 -> User4 (User3 follows User4)User5 -> User2 (User5 follows User2)3. Real-World Equivalents (Twitter / X)In platforms like Twitter, this data structure powers core features:Following List (Outgoing Edges): Who a specific user is subscribed to. For example, User2 follows User3.Follower List (Incoming Edges): Who is subscribed to a specific user. For example, User2 has two followers: User1 and User5.Network Topology / Chains: Tracing paths across the network (e.g., seeing how information or recommendations can flow from User1 $\rightarrow$ User2 $\rightarrow$ User3 $\rightarrow$ User4).Common Operations / Problems Solved by This StructureWhen engineers build systems like this, they typically design algorithms to answer these types of questions:Neighbor Queries ($O(1)$ time):"Who does User2 follow?" $\rightarrow$ [User3]"Who is following User2?" $\rightarrow$ [User1, User5]Pathfinding / Reachability (BFS/DFS):"Can User1 reach User4 through a chain of follows?" (In this case, Yes: User1 $\rightarrow$ User2 $\rightarrow$ User3 $\rightarrow$ User4).Mutual Connections:"Do UserX and UserY follow each other?" (Checking for bidirectional edges).Graph Metrics:Counting a user's In-Degree (follower count) to find popular accounts ("celebrities") or Out-Degree (following count) to find active connectors.
